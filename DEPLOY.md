# Deployment Runbook — Nexora ERP + CRM

Stack: **Render** (Express API) + **Neon** (PostgreSQL) + **Vercel** (React frontend) + **GitHub** (repo + CI).

Domains (suggested):
- Frontend: **nexora.dev** (Vercel — free plan supports custom domains)
- API: **nexora-api.onrender.com** (Render free subdomain — custom domains on Render require a paid plan)

> Because the API and frontend are on **different registrable domains** on the free tier, the refresh cookie must be `SameSite=None; Secure` (`COOKIE_SAME_SITE=none`), which is already configured in `render.yaml`. CSRF is still mitigated by the Origin assertion on `/auth/refresh` and `/auth/logout`. If you later put the API on `api.nexora.dev` (paid Render), switch `COOKIE_SAME_SITE` to `strict`.

## 1. Push the code to GitHub

The remote is already set to `https://github.com/MuditBaghel/Nexora.git`.

```powershell
# From C:\Users\baghe\Downloads\Nexora
git add -A
git commit -m "Production readiness: migrations, refresh-token auth, rate limiting, audit log, deploy configs"
git push -u origin master
```

If push prompts for credentials: install GitHub CLI (`winget install GitHub.cli`), run `gh auth login`, then `git push` again. Or create the empty repo at github.com/new named `Nexora` and push with a Personal Access Token.

## 2. Create the database (Neon)

1. Sign up at https://neon.tech (free tier).
2. **Create project** → name `nexora-db` (region close to you).
3. Copy the **connection string** (use the **direct connection** / pooler-less string for Node):
   `postgresql://user:pass@ep-xxx.region.aws.neon.tech/nexora-db?sslmode=require`
4. Keep it handy — it goes into Render in step 3.

## 3. Deploy the API (Render)

Option A — **Blueprint (easiest):**
1. https://render.com/new → **Blueprint** → connect the `MuditBaghel/Nexora` repo → follow the wizard.
2. It reads `render.yaml` (service `nexora-api`, runs migrations in `preDeployCommand`).
3. In the service's **Environment** tab, set `DATABASE_URL` to the Neon string from step 2. (`JWT_SECRET` is auto-generated; `CORS_ORIGIN=https://nexora.dev`, `COOKIE_SAME_SITE=none` are preset.)

Option B — **Dashboard (manual):**
1. New → **Web Service** → `MuditBaghel/Nexora` repo.
2. Root directory: `backend` · Build: `npm ci && npm run build` · Start: `npm run start` · Health check path: `/api/health`.
3. Add env vars: `NODE_ENV=production`, `DATABASE_URL=<Neon string>`, `JWT_SECRET=<long random>`, `CORS_ORIGIN=https://nexora.dev`, `COOKIE_SAME_SITE=none`, `JWT_EXPIRES_IN=15m`, `REFRESH_TOKEN_EXPIRES_IN=7d`.
4. **Pre-deploy** (migrations): shell → `npm run migrate`, or add a `preDeployCommand` after first deploy.

**Create the first users** (no sign-up API yet): in Render **Shell** run:

```bash
ALLOW_PRODUCTION_SEED=true npm run seed
```

This creates 4 demo users (admin/sales/warehouse/accounts@example.com, password `Password123!`). Change these passwords once the user-management module ships, or replace with your own admin via SQL (bcrypt hash).

Verify: `https://nexora-api.onrender.com/api/health` → `{"success":true,...}`

> Free-instance notes: sleeps after ~15 min idle (first request after idle takes ~50 s), 750 instance-hours/month.

## 4. Deploy the frontend (Vercel)

1. https://vercel.com/new → import `MuditBaghel/Nexora`.
2. Framework preset: **Vite** (auto-detected from `frontend/vercel.json`). Root directory: `frontend`.
3. Add env var **`VITE_API_URL=https://nexora-api.onrender.com/api`** (required at build time).
4. Deploy. Then **Settings → Domains** → add `nexora.dev` (and `www.nexora.dev`), follow Vercel's DNS instructions.

Verify: open `https://nexora.dev`, log in with `admin@example.com` / `Password123!`.

## 5. DNS

At your DNS provider, for `nexora.dev` follow **Vercel's** exact records (they give A/AAAA values per region). The API stays on the Render subdomain, so no DNS needed for it (free tier).

## 6. CI/CD

`.github/workflows/ci.yml` runs on every push/PR: backend typecheck + build + tests (against a Postgres service container) and frontend typecheck + build. Deploys are automatic: Render redeploys on `master` push (Blueprint) and Vercel builds previews + production.

## Security checklist (production)

- [ ] Strong `JWT_SECRET` (generated by Render — verify it's not the default)
- [ ] `CORS_ORIGIN` exactly `https://nexora.dev` (no trailing slash)
- [ ] HTTPS everywhere (Vercel + Render both force it; cookie is `Secure`)
- [ ] Rotate the demo passwords once user management is live
- [ ] Neon backups: enabled by default (point-in-time on paid tier); schedule a `pg_dump` job to object storage for offsite copies

## Backups & restore

```bash
# Backup (run via cron/CI, e.g. daily)
pg_dump "$DATABASE_URL" -F c -f nexora-$(date +%F).dump

# Restore
pg_restore -d "$DATABASE_URL" --clean --if-exists nexora-YYYY-MM-DD.dump
```

## Troubleshooting

| Symptom | Fix |
|---|---|
| Login works but session drops instantly | `COOKIE_SAME_SITE` must be `none` while API is on `*.onrender.com` and frontend on `nexora.dev`; both must be HTTPS |
| 429 on login | Login rate limit (10/min/IP) — check failed attempts / lockout in `audit_log` |
| CORS error in console | `CORS_ORIGIN` must equal the exact frontend origin |
| 401 after deploy | Migrations not run — run `npm run migrate` in Render Shell, or use the blueprint `preDeployCommand` |
| Health check failing | Confirm `DATABASE_URL` is the Neon **direct** connection string |
